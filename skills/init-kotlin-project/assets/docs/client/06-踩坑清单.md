# 06 踩坑清单

基于有赞 2.0 开发过程中实际遇到的问题。编码前通读一遍，评审时逐条对照。

本项目默认 **Vue 2 Options API**。本文件只收录「实际踩到、有现象或有报错」的问题；强制判定条件见 [docs/rules/消费端开发规则.md](../rules/消费端开发规则.md)，不要在别处再抄一份规则正文。

## 1. app.json

其中的属性 key 必须以 `/index` 结尾，否则可能引发问题（如小程序分享场景）。详见 [02-应用与页面配置.md](02-应用与页面配置.md)。

## 2. template 模板

- **最外层标签不允许动态展示**（如使用 `v-if`、`v-show`）。
- 不支持函数调用，若要处理数据展示，建议用 `computed`，或在给 `data` 赋值前处理。
- 不支持模板字符串，需用字符串拼接。
- **`:class` 只支持「纯数组」或「纯对象」，不支持数组里套对象**（如 `:class="['df-select', { 'df-select--filled': !!displayText }]"`），这类写法在消费端（尤其小程序）不生效，条件类名会被丢掉。正确写法二选一：
  - 纯数组 + 三元：`:class="['df-select', displayText ? 'df-select--filled' : '']"`
  - 纯对象（只写条件类名，固定类名留在静态 `class`）：`class="df-select" :class="{ 'df-select--filled': !!displayText }"`
  - 条件较多时优先在 `computed` 里拼好整串类名，模板直接 `:class="xxxClass"`。
- **`v-for` 的 `:key` 只能写「单个属性名」，不能写表达式**：编译到小程序后 `:key` 会原样落成 `wx:key`，而 `wx:key` 只接受 item 的属性名（或 `*this`）。写表达式不会报编译错误，但会出两类问题：
  - 表达式里带引号（如 `:key="item.pid + '-thumb'"`）会生成非法 JS（`'pid + '-thumb''`），小程序启动即报 `[渲染层错误] Uncaught SyntaxError: missing ) after argument list` + `$gwx is not defined`，**整页白屏**，且报错不指向具体文件。
  - 不带引号的表达式（如 `:key="item.code || item.name"`、`:key="tag + index"`）会变成 `wx:key="tag + index"`，运行时按属性名找不到值，key 失效。需要「组合 key」时请在数据处理阶段给 item 补一个唯一字段，再 `:key="item.xxx"`；纯数组可用 `:key="index"`。
  - 排查手段：用开发者工具自带的 wcc 编译器逐个编译 `dist/weapp` 下的 wxml，再对产物做 JS 语法检查，能精确定位到文件：`wcc <file.wxml> > /tmp/x.js && node --check /tmp/x.js`（wcc 位于 `wechatwebdevtools.app/Contents/Resources/app.asar.unpacked/node_modules/wcc-exec/wcc`）。
- **不要写原生 `input` / `span`**（小程序侧没有 `span`，原生 `input` 两端样式与事件也不一致）：
  - 输入框用 Tee UI `Field`：`import { Field } from "@youzan-cloud/tee-ui";` → `components: { "t-field": Field }` → `<t-field :value="xxx" @change="onChange" />`。`change` 抛的是 `{ value }`，不是原生 `event.detail.value`。
  - `placeholder-class` 在小程序 shadowRoot 下不生效，占位符样式统一用 `placeholder-style`（字号写 `calc(100vw / 750 * N)`，与 `rpx()` 等价）。
  - `t-field` 根节点是 `t-cell`，自带白底、上下 `10px` / 左右 `16px` 内边距与下边框：必须 `:border="false"`。
  - **class 到不了 `t-cell`（小程序专有）**：H5 下传给 `t-field` 的 class 会落到 `t-cell` 根节点，小程序下只落在 `t-field` 的组件宿主节点上，内边距 / 行高 / 白底对内部的 `t-cell` 全部失效（表现为 `padding: 0` 不起作用、输入行明显偏高）。这类外观样式必须用组件自身的 `custom-style` 下发：`<t-field :custom-style="'padding: 0; height: calc(100vw / 750 * 36); background-color: transparent;'" />`（`Field` 声明了 `customStyle` 并原样绑到 `t-cell` 根节点 `style`，两端一致）；class 只留 `flex` / `min-width` 这类宿主节点布局。
  - 内部输入区在 H5 用 `::v-deep .t-field__input` 覆盖 `color` / `height` / `font-size`；小程序 shadowRoot 下 `::v-deep` 不生效，文字样式靠 `custom-style` 的 `height` / `line-height` 与 `placeholder-style` 对齐。
  - 文本用 `text`、布局用 `view`，不要用 `span` / `div` 等 H5 标签。
- **布尔属性必须显式绑定**：写 `:hide-auth-fields="true"` / `:scroll-y="true"`，不要简写成 `hide-auth-fields` / `scroll-y`。简写在多端编译后取值不确定，且无法表达 `false`。

## 3. script 模块

- 若 `watch` 不生效，需使用 `@youzan-cloud/developer-client-presets` **1.4.18 以上**版本的依赖（本仓库当前为 `1.4.40`）。
- `.js` 文件中注释**不要**出现 `createPage` 或 `extendPage` 的关键词。**后果与排查**：Tee 编译时会按关键字把该 `.js` 判定为页面入口，用 `const mixin = function () { ... }` 包裹整个文件，于是文件内的 `export` 报
  `Syntax Error: 'import' and 'export' may only appear at the top level`，且报错行号会偏移（表现为第 7~9 行莫名出现 `const wx = undefined;`）。编译产物落在 `node_modules/lib/packages/<包名>/<文件>.js`，直接看该文件首行是否为 `const mixin = function` 即可确认；正常文件首行应是 `const App = undefined;`。**`constants.js`、`utils` 等被页面 import 的普通模块同样适用此规则**，不仅仅是页面入口文件。
- `index.js`（页面入口）里**不要**写 `import page from "./page.vue"`：`page` 由 Tee 注入为全局变量，直接 `render: (h) => h(page)` 即可；显式 import 会被当作普通模块处理而破坏页面识别。需要跨文件复用的常量（如触底事件名）仍可正常 `import { XXX } from "./constants"`。
- 独立 `.js` 文件不能使用可选链式语法（用 `||`、提前处理初始值或普通判空替代）；`.vue` 文件中可以正常使用，**能链式调用时优先使用**。
- **小程序**环境自定义组件 `dataReady` 不生效，疑似与文件名称有关，相关问题已反馈，未修复。
- **页面初始化请求不要写在 `created` / `beforeMount` / `mounted`**：这三个钩子可能早于 `this.yz` 注入完成，`this.yz.app` 为空、`this.yz.data.user` 取不到 `yzOpenId`、`this.yz.getPageQuery()` 拿不到参数都会随机出现；首屏请求统一放 `dataReady`（原因与示例见 [03-生命周期与页面入口.md](03-生命周期与页面入口.md)）。
- 部分标品页面组件无 `name` 会报错失效，建议所有组件添加 `name`。
- 严格区分全局 `yz.*` 与页面实例 `this.yz.*`：`this.yz` 只有 `app` / `data` / `getPageQuery` / `queryComponentById`，`navigateTo`、`back`、`event`、`getEnvSync`、`getSystemInfo`、`setClipboardData` 等一律用全局 `yz.`。
- `data` / `computed` 中的数据更新时，若赋值 / 返回值为 `undefined` **不会触发页面更新**；如需清空请赋值 / 返回 `null`。

## 4. style 模块

- 样式引入用 `@import "url"`。
- 样式穿透用 `::v-deep`。
- 行内样式 `style` 不能换行，标品构建会失败。
- 本项目 `src/styles/global.scss` 已内置 `@function rpx($value)`，样式单位优先用 `rpx`（通过相对路径引入 `styles/global.scss`）；未内置该函数的工程用 `px`。

## 5. 多端组件

- 有 `pid` 属性的多端组件建议全局唯一，否则可能导致组件异常，推荐直接在 `data` 中生成随机 `pid`。

## 6. 开放组件

- 必须放在页面层或插槽层，不能放在自定义组件中。
- 内部不建议使用 Tee UI 组件，大概率导致开放组件失效。
- **开放组件根节点上的 class 不一定生效**：如把 `flex: 1`、外边距写在 `<user-auth class="...">` 上，H5 实测不生效，包在里面的按钮会缩成内容宽度。宽度、间距要写在外层 `view` 上，内部按钮用 `width: 100%`。参考 `packages/activity-detail` 的报名按钮和 `packages/dealer-detail` 的打卡按钮：

```html
<view class="action-auth-wrap"><!-- flex: 1; margin-left: ... -->
  <user-auth cloud-id="xxxUserAuth" :auth-type-list="['mobile']">
    <view class="action-button"><!-- width: 100% -->打卡</view>
  </user-auth>
</view>
```

## 7. 自定义 js 文件

- **谨慎导出文件内变量**：导出的变量在所有 `import` 它的文件中会被重新声明，一处修改，其他引入方仍是旧值。

```javascript
export const storeState = {};
export function setState(key, value) {
    storeState[key] = value;
}
```

```javascript
import { storeState, setState } from "导出变量";
setState('name', 'lue');
// 输出：{ name: "lue" } —— 同一文件内读到的值已更新
console.log(storeState);
```

```javascript
import { storeState } from "导出变量";

// 等待文件1执行
await runFile1();
// 输出：{} —— 另一个文件中拿到的仍是旧值
console.log(storeState);
```

需要跨文件共享状态时，使用 `yz.event` 或 `src/utils/store/`，不要依赖导出的可变对象。
