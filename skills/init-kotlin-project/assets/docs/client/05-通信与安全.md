# 05 通信与安全

## 1. 通信机制

优先使用开放框架提供的通信能力，**不使用** `window`、`getApp`、全局变量等非官方通道。

| 方向 | 方式 |
| --- | --- |
| App → 页面 | 页面中用 `yz.event.on` 监听，App 中用 `yz.event.trigger` 触发 |
| 页面 → App | 通过 `this.yz.app.xxx` 调用 `extendApp` 中的方法或属性 |
| 组件 → App | 通过 `this.yz.app.xxx` 调用 |
| 页面 → 页面插槽组件 | 在 `dataReady` 中通过 `this.yz.refs["组件name"]` 获取组件实例 |
| 插槽组件 → 页面 | 通过 `this.yz.page.xxx` 调用 `extendPage` 中的方法或属性 |
| 应用实例 → 应用级组件 | 通过 `this.yz.refs["组件name"]` 获取组件实例 |
| 组件 → 组件 | 优先 props、events、ref；复杂跨层通信再考虑 `yz.event` |

### 1.1 this.yz.refs 使用时机

- `this.yz.refs` 获取时机较晚，建议在 `dataReady()` 后使用，过早访问可能是 `undefined`。
- `this.yz.refs` 的 key 与组件 `name` 相关，因此插槽组件必须设置稳定的 `name`。

## 2. 全局 yz API 与页面实例 API

严格区分全局 `yz.*` API 和页面实例 `this.yz.*` 能力，以文档中的调用对象为准：

| 错误 | 正确 |
| --- | --- |
| `this.yz.navigateTo` | `yz.navigateTo` |
| `yz.getPageQuery` | `this.yz.getPageQuery` |

不确定时先查对应 API 文档，不要凭直觉迁移。

## 3. 数据获取

需要 yz 数据的最新值时**不要使用 `computed`**，必须使用 `this.yz.watch` 监听：

```javascript
// 正确示例（全局数据）
this.yz.watch('user', (user) => {
  console.log(user);
});

// 正确示例（页面数据：下单页）
this.yz.watch('payment', (payment) => {
  console.log(payment);
});

// 错误示例：api 不能监听对象的某个属性，只能监听对象本身
this.yz.watch('user.info', (info) => {
  console.log(info);
});
```

## 4. 安全与权限

所有三方代码运行在独立沙箱中，数据、事件、接口、报错互相隔离。

禁止或避免使用以下非多端 API，必须优先使用开放 API 替代：

| 类别 | 禁用 API |
| --- | --- |
| 浏览器 API | `top`、`parent`、`window`、`frames`、`location`、`frameElement`、`localStorage`、`sessionStorage` |
| 小程序 API | `wx`、`getApp`、`getCurrentPages`、`Page`、`Components`、`App` |
