# 02 独立页面与路由

## 1. 多页面自动发现机制

`vite.config.ts` 使用 `MultiPageAutoPlugin` 自动发现多页面入口。`src/pages/` 下的页面目录存在 `main.tsx` 时，该目录会被识别并打包为一个独立页面，构建产物、FTL 视图和后端访问路径都以页面目录名对应：`<页面目录>.html`、`<页面目录>.ftl`、`/view/<页面目录>`。

## 2. 两个入口，缺一不可

一个独立页面需要登记两处入口，两者职责不同：

| 入口 | 位置 | 作用 |
| --- | --- | --- |
| 构建入口 | `src/pages/<页面目录>/main.tsx` | 决定构建产物与部署形态，只在构建产物和部署环境生效 |
| 本地调试入口 | `src/router/routes.tsx` | 决定 `npm run dev` 打开的默认应用中能否进入该页面 |

## 3. 新增独立页面

新增独立页面时必须创建：

```plaintext
src/pages/<page-name>/
├── main.tsx                       # 独立构建入口，负责挂载 React 应用
├── App.tsx                        # 单页应用的根页面组件
└── router/
    └── index.tsx                  # 该独立页面内部的 SPA 路由
```

`main.tsx` 只负责以下内容：

- 创建并挂载 React Root。
- 引入该入口需要的全局样式。
- 注入 Router、主题、KeepAlive 等应用级 Provider。

不得在 `main.tsx` 中编写查询、提交、权限判断等页面业务逻辑。

除上述文件外，新增独立页面还必须在 `src/router/routes.tsx` 中登记本地调试路由，见第 4 节。

## 4. 本地调试路由登记

新增独立页面时必须同时在 `src/router/routes.tsx` 中登记本地调试路由，否则本地无法从默认应用的菜单进入该页面。

`npm run dev` 只提供默认应用入口：本地请求任意 `/<页面目录>.html` 都会被 SPA 回退到默认应用的 `index.html`，独立页面的 `main.tsx` 只在构建产物和部署环境（`/view/<页面目录>`）生效。因此本地调试必须通过默认应用的路由进入页面。

在 `src/router/routes.tsx` 的 `LayoutPage` 子路由中追加一项：

```tsx
{
  path: "/dealer",
  title: "经销商管理",
  keepAlive: true,
  element: createLazyLoad(lazy(() => import("@/pages/dealer/App"))),
}
```

登记时遵循以下约定：

- `element` 直接指向该页面的 `App.tsx`；不要把页面内部的 `router` 整体挂到默认应用，它只服务于独立构建入口。
- `path` 使用页面目录名，例如 `src/pages/dealer/` 对应 `/dealer`，与该页面的构建入口 `dealer.html`、后端视图 `/view/dealer` 保持一致。
- `title` 必填，同时作为默认应用的菜单名称和面包屑文案。
- 需要保留页面状态时设置 `keepAlive: true`；不需要出现在菜单中的页面设置 `hidden: true`，仍可通过地址直接访问。
- 页面包含详情、编辑等关联页面时，为这些页面补充平级调试路由，路径使用 `/<页面目录名>/<业务子路径>`；调试路由挂载的是页面根组件，不含 `Outlet`，不要把它们登记为当前路由的子路由。
- 调试路由只服务于本地调试，不参与生产环境 `main.tsx` + 页面内部 `router` 的加载链路。

仓库中另有 `src/router/autoRoutes.tsx`（按 `src/pages/**/App.tsx` 自动生成路由），当前默认应用接入的仍是 `src/router/routes.tsx`，新增独立页面请按本节手工登记。

## 5. 关联页面组织

如果独立页面还包含列表、详情、编辑等关联页面，应将它们统一注册到该独立页面的 `router` 中，通过 React Router 组成一个单页应用（SPA）。关联页面不得分别添加 `main.tsx`，否则会被拆成多个独立构建入口。

路由页面优先使用 `lazy` 和 `createLazyLoad` 按需加载。可参考：

- `src/pages/list/main.tsx`
- `src/pages/list/router/index.tsx`
- `src/components/LazyLoad/index.tsx`

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 本地 `npm run dev` 进不去新页面 | 未在 `src/router/routes.tsx` 登记调试路由 |
| 访问 `/<页面目录>.html` 落到默认应用 | 独立页面的 `main.tsx` 只在构建产物与部署环境生效，本地调试必须走默认应用路由 |
| 一个页面被拆成多个构建产物 | 关联页面误加了自己的 `main.tsx`，应通过该页面的 `router` 组织 |
| 改了 `app.json` 类似配置不生效 | 本工程无此机制；检查 `vite.config.ts` 的 `MultiPageAutoPlugin` 与页面 `main.tsx` 是否存在 |
