# 07 命令与检查清单

## 1. 执行位置与包管理器

所有命令必须在 `${PROJECT_NAME}-ui/vite-react-page` 工程目录中执行，不要在仓库根目录或其他前端工程中执行。本工程使用 **npm**（仓库内为 `package-lock.json`）；消费端工程使用 yarn，两者不要混用。

## 2. 常用命令

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动管理后台开发环境（默认应用入口；本地调试独立页面须先在 `src/router/routes.tsx` 登记路由） |
| `npm run dev:scan` | 启动带 React Scan 的开发环境（`vite --mode scan`），用于排查多余渲染 |
| `npm run openapi` | 先生成 OpenAPI spec 再执行 `openapi-ts`，产出 `src/api/generated/` |
| `npm run build` | 构建管理后台工程，仅在任务需要构建验证时执行 |

## 3. 多端适配边界

**不做多媒体适配**（即屏幕 / 分辨率响应式适配）。只按设计稿的目标屏幕尺寸实现：

- 不写媒体查询（`@media`）。
- 不使用 Tailwind 响应式断点前缀（`sm:`、`md:`、`lg:`、`xl:`、`2xl:`）。
- 不为其他分辨率或设备尺寸单独适配。
- 布局差异用栅格、Flex 与容器宽度约束表达，不用断点。

## 4. 提交前检查清单

提交新页面前至少确认：

- [ ] 已先检查并复用 `src/components/`、`src/hooks/`、`src/utils/` 和 `src/api/`。
- [ ] 独立页面已配置唯一的 `main.tsx`，关联页面已通过 Router 组织为 SPA。
- [ ] 独立页面已在 `src/router/routes.tsx` 登记本地调试路由（`path` 使用页面目录名，`element` 指向该页面 `App.tsx`），`npm run dev` 可从默认应用菜单进入该页面。
- [ ] `main.tsx` 只承担挂载和 Provider 配置，没有业务逻辑。
- [ ] `App.tsx` 只承担页面编排，没有堆积组件、工具、类型和大段样式。
- [ ] 一个组件文件只包含一个 React 组件，可独立命名的子组件已经拆分。
- [ ] 页面已按需拆分 `components/`、`hooks/`、`utils.ts`、`constants.ts`、`types.ts` 和 `styles.ts`。
- [ ] 样式优先使用 Tailwind CSS，复杂样式才使用 styled-components。
- [ ] 不同页面和组件的 styled-components 已放入各自独立的样式文件。
- [ ] 没有把页面私有样式写入全局样式文件，也没有无作用域覆盖 Ant Design。
- [ ] API 优先通过 OpenAPI 生成并复用统一请求配置，未手动修改生成文件。
- [ ] 没有使用 `sm:`、`md:`、`lg:` 等响应式断点前缀或 `@media`，布局只针对设计稿目标屏幕尺寸。
- [ ] 代码通过项目已有的 TypeScript、ESLint 和 Prettier 检查（不为检查新增依赖）。

## 5. 自检命令

```shell
cd ${PROJECT_NAME}-ui/vite-react-page

# 检查是否有响应式断点前缀（应无输出）
grep -rnE '"[^"]*\b(sm|md|lg|xl|2xl):' src --include="*.tsx" --include="*.ts"

# 检查是否有 @media（应无输出）
grep -rn "@media" src --include="*.tsx" --include="*.ts"

# 检查 App.tsx 是否同时定义了多个组件（人工确认输出是否为单文件多组件）
grep -rn "^const .*= () =>\|^function [A-Z]" src/pages/*/App.tsx
```
