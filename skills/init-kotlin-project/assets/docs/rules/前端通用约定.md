# 前端通用约定

前端分为**两个独立工程**，技术栈、目录结构、生成文件与运行命令均不通用。开始开发前必须先确认目标端，不得混用。

| 端 | 目录 | 技术栈 | 必读文档 | 强制规则 |
| --- | --- | --- | --- | --- |
| 消费端 | `${PROJECT_NAME}-ui/cloud/client` | Vue + Tee 多端框架，支持 H5 与微信小程序 | [消费端开发文档](../client/README.md) | [消费端开发规则.md](消费端开发规则.md) |
| 管理后台 | `${PROJECT_NAME}-ui/vite-react-page` | React 18 + Vite 5 + TypeScript + React Router + Ant Design | [管理后台开发文档](../admin/README.md) | [管理后台开发规则.md](管理后台开发规则.md) |

## 1. 命令执行位置

所有前端命令必须在对应工程目录内执行，**不要在仓库根目录、也不要在另一端工程中执行**。

## 2. 不做多媒体适配（两端共同硬规则）

前端**不做多媒体适配**（即屏幕 / 分辨率响应式适配）：两个工程都只按设计稿的目标屏幕尺寸实现，不写媒体查询、不使用响应式断点（如 Tailwind 的 `sm:`、`md:`、`lg:`），不为其他分辨率或设备尺寸单独适配。

## 3. API 契约

- 两份生成产物均**不得手动编辑**：
  - 消费端：`${PROJECT_NAME}-ui/cloud/client/src/api/sdk.gen.js`
  - 管理后台：`${PROJECT_NAME}-ui/vite-react-page/src/api/generated/`
- 修改接口前，先按 [接口与Swagger规范.md](接口与Swagger规范.md) 确认 `nickname` 命名，因为它是前端生成的方法名。
- 如接口暂时无法生成，先保留页面逻辑和 Mock，或说明原因并确认临时方案，**不得自行固化未经确认的接口契约**。

## 4. 前后端并行开发

- 并行前先约定：接口路径、请求方法、字段、分页结构、错误码、状态流转，再分别实现。
- 页面可以先实现交互逻辑并使用 Mock 数据，但**不得**因此创建一套绕开 OpenAPI 的临时 API 层。

## 5. 检查与验证

- 完成修改后，根据变更范围运行对应工程**已有**的 TypeScript、ESLint、Prettier、测试或构建检查。
- 不为检查额外引入依赖。
- 构建命令（`npm run build`）仅在任务需要构建验证时执行，不作为常规检查手段。

## 6. 常见错误

| 错误做法 | 正确做法 |
| --- | --- |
| 在仓库根目录执行 `npm run dev` | 进入对应工程目录再执行 |
| 手改 `sdk.gen.js` / `src/api/generated/` | 改后端注解后重新执行 `npm run openapi` |
| 用 `sm:grid-cols-2` 做多分辨率适配 | 只按设计稿目标宽度实现，去掉断点前缀 |
| 页面里自建 axios 实例 | 管理后台复用 `src/api/config.ts`；消费端复用生成 SDK |
