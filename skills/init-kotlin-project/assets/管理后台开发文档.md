# 管理后台开发文档

本文档适用于 `yf-brp-ui/vite-react-page` 管理后台 React 工程，约定工程目录职责、独立页面入口、页面文件拆分、公共能力复用及样式组织方式。

## 1. 工程概览

工程使用 React、TypeScript、Vite、React Router、Ant Design、Tailwind CSS 和 styled-components。源码通过 `@/` 别名引用 `src/` 下的模块。

开发管理后台页面前必须遵循以下优先级：

1. 优先复用 `src/components/` 中已有的公共组件。
2. 优先复用 `src/hooks/` 中已有的通用 Hook。
3. 优先复用 `src/utils/`、`src/types/` 和 `src/api/` 中已有能力。
4. UI 基础能力优先使用 Ant Design，不重复封装功能相同的基础组件。
5. 只有现有能力不能满足需求时，才新增页面私有实现或公共实现。

新增代码前应先搜索上述目录。能够通过配置、组合或小范围扩展满足需求时，不得在页面目录内重新实现一套相同能力。

## 2. 工程目录结构

```plaintext
yf-brp-ui/vite-react-page/
├── config/                         # TypeScript 路径等工程配置
├── mock/                           # 本地开发 Mock 数据与接口
├── src/
│   ├── api/                        # 请求配置、生成的 SDK 与接口导出
│   │   ├── generated/              # OpenAPI 自动生成代码，不得手动修改
│   │   ├── config.ts               # Axios 实例、拦截器及生成 SDK 的运行时配置
│   │   └── index.ts                # 手动维护的公共接口与相关类型
│   ├── components/                 # 跨页面复用的公共组件
│   ├── hooks/                      # 跨页面复用的通用 React Hook
│   ├── layout/                     # 管理后台公共布局及导航组件
│   ├── pages/                      # 页面与独立页面构建入口
│   ├── router/                     # 默认应用路由、路由工具及路由公共组件
│   ├── store/                      # 跨层级共享状态与 Provider
│   ├── styles/                     # 应用级全局样式和公共样式容器
│   ├── types/                      # 跨模块复用的公共 TypeScript 类型
│   ├── utils/                      # 无业务状态的公共工具函数
│   ├── App.tsx                     # 默认应用根组件及全局 Provider
│   └── main.tsx                    # 默认应用挂载入口
├── index.html                      # Vite HTML 模板
├── openapi-ts.config.ts            # OpenAPI SDK 生成配置
├── tailwind.config.js              # Tailwind CSS 配置
├── tsconfig.json                   # TypeScript 编译配置
└── vite.config.ts                  # Vite、MultiPageAutoPlugin 等构建配置
```

### 2.1 目录职责

| 目录 | 职责 | 约束 |
| --- | --- | --- |
| `src/api/` | 请求基础配置、接口 SDK 和接口类型 | 后端提供 Swagger/OpenAPI 时优先执行 `npm run openapi` 生成 SDK；不得直接修改 `generated/` |
| `src/components/` | 与具体业务页面无关、可跨页面复用的组件 | 新页面必须先检查此目录，禁止重复实现已有组件 |
| `src/hooks/` | 请求、列表、弹窗、事件等可复用状态逻辑 | 页面中出现同类逻辑时优先调用已有 Hook |
| `src/layout/` | 页面框架、菜单、面包屑等整体布局 | 不放具体业务页面逻辑 |
| `src/pages/` | 页面入口及页面私有组件、Hook、类型和工具 | 页面私有实现就近维护，不要提前上提为公共能力 |
| `src/router/` | 默认路由、路由格式化及路由级公共组件 | 业务路由配置应保持声明式，不在配置文件中编写业务请求逻辑 |
| `src/store/` | 需要跨组件树共享的状态与上下文 | 局部页面状态不要放入全局 Store |
| `src/styles/` | 全局重置、主题衔接和真正跨页面的公共样式 | 禁止把所有页面或组件样式集中到一个文件 |
| `src/types/` | 多个模块共同使用的类型 | 页面专属类型应放在对应页面的 `types.ts` |
| `src/utils/` | 无 React 状态、无页面副作用的公共函数 | 页面专属转换逻辑应放在对应页面的 `utils.ts` |

## 3. 独立页面与路由

`vite.config.ts` 使用 `MultiPageAutoPlugin` 自动发现多页面入口。`src/pages/` 下的页面目录存在 `main.tsx` 时，该目录会被识别并打包为一个独立页面。

### 3.1 新增独立页面

新增独立页面时必须创建：

```plaintext
src/pages/<page-name>/
├── main.tsx                       # 独立构建入口，负责挂载 React 应用
├── App.tsx                        # 单页应用的根页面组件
└── router/
    └── index.tsx                  # 该独立页面内部的 SPA 路由
```

`main.tsx` 只负责以下内容：

- 创建并挂载 React Root。
- 引入该入口需要的全局样式。
- 注入 Router、主题、KeepAlive 等应用级 Provider。

不得在 `main.tsx` 中编写查询、提交、权限判断等页面业务逻辑。

### 3.2 关联页面组织

如果独立页面还包含列表、详情、编辑等关联页面，应将它们统一注册到该独立页面的 `router` 中，通过 React Router 组成一个单页应用（SPA）。关联页面不得分别添加 `main.tsx`，否则会被拆成多个独立构建入口。

路由页面优先使用 `lazy` 和 `createLazyLoad` 按需加载。可参考：

- `src/pages/list/main.tsx`
- `src/pages/list/router/index.tsx`
- `src/components/LazyLoad/index.tsx`

## 4. 页面目录与文件设计

### 4.1 推荐页面结构

页面应按实际职责按需创建文件，不要求空目录占位。一个包含列表、筛选、编辑弹窗和详情页的业务页面推荐结构如下：

```plaintext
src/pages/order/
├── main.tsx                       # 仅独立页面需要
├── App.tsx                        # 页面根组件，只负责整体编排
├── components/
│   ├── OrderSearch/
│   │   ├── index.tsx              # 搜索区域组件
│   │   ├── types.ts               # 仅该组件使用的类型
│   │   └── styles.ts              # 仅该组件使用的 styled-components
│   ├── OrderTable/
│   │   ├── index.tsx
│   │   ├── constants.ts
│   │   └── styles.ts
│   └── OrderEditModal/
│       ├── index.tsx
│       ├── types.ts
│       └── styles.ts
├── hooks/
│   └── useOrderList.ts            # 页面私有状态与业务流程
├── router/
│   └── index.tsx                  # 独立页面内部路由
├── constants.ts                   # 页面级常量和静态配置
├── types.ts                       # 页面级 Props、DTO 衍生类型等
├── utils.ts                       # 页面级纯函数、格式转换函数
└── styles.ts                      # 仅 App 根布局使用的样式
```

文件较少时使用 `types.ts`、`utils.ts`、`constants.ts` 单文件即可；当同一职责内出现多个明确主题时，再拆成对应目录。不要为了形式创建只有转发导出的多层目录。

### 4.2 `App.tsx` 职责

`App.tsx` 是页面编排层，应负责：

- 组合搜索区、操作区、表格、详情和弹窗等业务组件。
- 连接页面级 Hook 返回的状态与操作。
- 处理页面级布局和路由出口。

`App.tsx` 不应长期承载以下内容：

- 大段表格列定义、表单项定义或静态选项，应移入 `constants.ts` 或对应组件。
- 可独立命名的搜索区、表格、表单、弹窗和详情区域，应移入 `components/`。
- 数据格式转换、参数组装等纯函数，应移入 `utils.ts`。
- 复杂请求状态和业务流程，应移入页面私有 Hook。
- 大段 styled-components 定义，应移入 `styles.ts`。

### 4.3 组件单一职责

组件必须尽量保持单一职责，并遵循以下规则：

- 一个组件文件只定义一个 React 组件。
- 不得在同一个 `.tsx` 文件中同时定义页面组件、弹窗组件、表格组件等多个组件。
- 发现可独立命名、独立接收 Props 或独立维护状态的 UI 区域时，应拆分为单独文件。
- 子组件仅服务于一个父组件时，放入父组件目录；被多个页面使用时，提取到 `src/components/`。
- `index.ts` 仅用于稳定导出路径，不在其中堆放多个组件实现。
- 普通纯函数不应伪装成组件；放入 `utils.ts` 并使用动词开头的名称。

推荐：

```plaintext
components/OrderTable/
├── index.tsx
├── OrderStatus.tsx
├── constants.ts
├── types.ts
└── styles.ts
```

禁止：

```tsx
// OrderPage.tsx
const OrderSearch = () => { /* ... */ };
const OrderTable = () => { /* ... */ };
const OrderEditModal = () => { /* ... */ };
export default function OrderPage() { /* ... */ }
```

### 4.4 文件职责

| 文件或目录 | 内容 |
| --- | --- |
| `components/` | 页面私有展示组件和交互组件 |
| `hooks/` | 页面私有状态组合、请求流程及副作用 |
| `constants.ts` | 表格列基础配置、枚举映射、静态选项等常量 |
| `types.ts` | 页面或组件 Props、表单值、视图模型等类型 |
| `utils.ts` | 参数转换、数据格式化和其他纯函数 |
| `styles.ts` | 当前页面根组件或当前组件的 styled-components |
| `router/index.tsx` | 当前独立页面内部路由 |

不要把 API 请求、常量、类型、工具函数和样式全部写入 `App.tsx`。

## 5. 公共组件复用规范

开发页面前必须检查 `src/components/`。已有公共组件能够满足需求时必须优先使用；存在少量通用差异时，优先为公共组件增加兼容配置，并确认不会破坏既有调用方。仅与单一业务强相关的组件保留在页面目录。

| 公共组件 | 主要职责 | 优先使用场景 |
| --- | --- | --- |
| `Action` | 为操作节点组合 Button 和 Popconfirm | 表格操作列中的按钮、二次确认操作 |
| `AsyncButton` | 自动维护异步点击操作的 loading 状态 | 提交、导出、同步等异步按钮 |
| `AutoActions` | 展示有限数量的操作项，并将超出项收纳到 Popover | 表格操作列按钮较多的场景 |
| `CustomModal` | 统一 Modal、Form 提交和确认 loading | 新增、编辑、确认类弹窗 |
| `DropFolderUpload` | 拖拽文件或文件夹、递归提取图片并上传 | 批量图片和文件夹图片上传 |
| `LazyLoad` / `createLazyLoad` | 为 React 懒加载组件提供统一 Suspense Loading | 路由懒加载和大型模块按需加载 |
| `Loading` | 统一页面或区域加载反馈 | Suspense fallback、页面加载占位 |
| `Search` | 通过配置生成查询表单，支持查询、重置和自定义字段 | 列表页筛选条件区域 |
| `Template` | 渲染嵌套路由的 `Outlet` | 需要纯路由分组的父级节点 |
| `UploadImage` | 图片上传、大小校验和预览 | 单张或多张普通图片上传 |
| `UploadSorter` | 图片上传、预览、删除和拖拽排序 | 需要调整图片顺序的上传场景 |

使用公共组件时应直接阅读其 Props 类型和当前实现，不要根据组件名猜测行为。公共组件新增通用能力后，应保持既有 Props 的兼容性。

## 6. 公共 Hook 复用规范

开发请求、列表、弹窗和事件逻辑前必须检查 `src/hooks/`。禁止在每个页面重复编写 loading、分页、请求取消、弹窗挂载和事件解绑等通用逻辑。

| Hook | 主要职责 | 优先使用场景 |
| --- | --- | --- |
| `useConfigurableEffect` | 控制首次执行、仅执行一次及消费路由 state 的 Effect | 需要跳过首次执行或读取一次性路由状态 |
| `useEventListener` | 注册并自动清理 Window、Document 或元素事件 | resize、scroll、keydown 等原生事件监听 |
| `useFetchList` | 管理列表请求、分页、搜索条件、loading 和列表更新 | 后台分页列表页 |
| `useModal` | 在统一 Provider 环境中挂载弹窗并返回 Promise 化打开方法 | 命令式打开新增、编辑、详情弹窗 |
| `useRequest` | 管理通用异步请求、loading、结果和取消请求 | 非列表接口请求或页面初始化请求 |
| `useSubEvent` / `dispatchSubEvents` | 提供带清理机制的跨组件事件订阅与派发 | 无直接父子 Props 链路的局部事件协作 |

页面私有 Hook 应放在对应页面的 `hooks/` 中。只有逻辑与具体业务无关、接口稳定且预计会被多个页面使用时，才上提到 `src/hooks/`。

## 7. 样式设计规范

### 7.1 样式技术优先级

样式实现按以下优先级选择：

1. 优先使用 Tailwind CSS 工具类完成布局、间距、尺寸、排版和常规视觉样式。
2. Tailwind CSS 难以清晰表达动态主题、复杂选择器、组件内部状态或第三方组件覆盖时，使用 styled-components。
3. 只有全局重置、全局动画和跨应用公共规则可以写入 `src/styles/index.css`。
4. 行内 `style` 仅用于运行时计算值或第三方组件明确要求的属性，不用于承载成片静态样式。

### 7.2 样式文件拆分

不同页面、不同组件的样式必须写入各自独立文件，禁止把所有样式集中到一个页面级或全局样式文件中。

- `App.tsx` 的根布局样式放在同级 `styles.ts`。
- `OrderTable` 的样式放在 `components/OrderTable/styles.ts`。
- `OrderEditModal` 的样式放在 `components/OrderEditModal/styles.ts`。
- 只使用 Tailwind CSS 的组件无需创建空 `styles.ts`。
- styled-components 的名称应体现组件语义，例如 `OrderTableContainer`，不要使用 `Wrapper1`、`Box2` 等无意义名称。
- 覆盖 Ant Design 样式时限制选择器作用域，避免影响其他页面。
- 需要读取主题颜色时优先使用 Ant Design Token，不要复制硬编码主题色。

禁止以下组织方式：

```plaintext
src/styles/
└── all-pages.ts                  # 集中存放所有页面和组件样式
```

推荐以下组织方式：

```plaintext
src/pages/order/
├── styles.ts                    # 仅 order/App.tsx 使用
└── components/
    ├── OrderTable/styles.ts     # 仅 OrderTable 使用
    └── OrderEditModal/styles.ts # 仅 OrderEditModal 使用
```

## 8. TypeScript 与命名规范

- React 组件和组件目录使用 PascalCase，例如 `OrderTable.tsx`、`OrderEditModal/`。
- Hook 使用 `use` 前缀和 camelCase，例如 `useOrderList.ts`。
- 工具函数使用 camelCase，并用动词描述行为，例如 `formatOrderAmount`。
- 常量使用能够表达语义的名称；真正不可变的模块级常量可使用大写下划线形式。
- Props 类型使用 `<ComponentName>Props` 命名，并优先放在组件同级 `types.ts` 或组件文件中。
- 仅作为类型使用的依赖必须通过 `import type` 引入。
- 跨目录引用优先使用 `@/` 别名，同目录内部文件使用相对路径。
- 禁止无必要地使用 `any`；接口响应、表单值、表格行和路由状态应定义明确类型。
- 不直接修改 OpenAPI 生成的 `src/api/generated/` 文件。

## 9. 新页面开发检查清单

提交新页面前至少确认：

- 已先检查并复用 `src/components/`、`src/hooks/`、`src/utils/` 和 `src/api/`。
- 独立页面已配置唯一的 `main.tsx`，关联页面已通过 Router 组织为 SPA。
- `main.tsx` 只承担挂载和 Provider 配置，没有业务逻辑。
- `App.tsx` 只承担页面编排，没有堆积组件、工具、类型和大段样式。
- 一个组件文件只包含一个 React 组件，可独立命名的子组件已经拆分。
- 页面已按需拆分 `components/`、`hooks/`、`utils.ts`、`constants.ts`、`types.ts` 和 `styles.ts`。
- 样式优先使用 Tailwind CSS，复杂样式才使用 styled-components。
- 不同页面和组件的 styled-components 已放入各自独立的样式文件。
- 没有把页面私有样式写入全局样式文件，也没有无作用域覆盖 Ant Design。
- API 优先通过 OpenAPI 生成并复用统一请求配置，未手动修改生成文件。
- 代码通过项目已有的 TypeScript、ESLint 和 Prettier 检查。
